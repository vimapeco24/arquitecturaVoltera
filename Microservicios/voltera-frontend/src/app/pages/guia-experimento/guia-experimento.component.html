🧭 Guía · Cómo funciona el experimento

Guía del Experimento Voltera

Recorrido detallado de cómo debe funcionar el experimento de punta a punta: el ciclo comercial de las comunidades energéticas (6 pasos) más la cadena de telemetría orientada a eventos (EDA). Cada bloque está alineado con los microservicios reales desplegados y las rutas que consume este mismo front a través del API Gateway WSO2.

🎯 Objetivo

Demostrar una arquitectura de nueva generación para comunidades energéticas: microservicios por dominio, comunicación síncrona (REST a través del gateway) y asíncrona (eventos sobre Redpanda), con persistencia CQRS, idempotencia por inbox, autoescalado dirigido por eventos (KEDA) y observabilidad completa. El experimento valida que un prosumidor pueda tarificar, liquidar, facturar y pagar su energía, y que la telemetría de los medidores fluya y escale de forma resiliente.

🔌 Cómo se conecta el front con el backend

  1. 1
    Token OAuth2 El navegador pide un token a /api/token (BFF serverless) → server-to-server a WSO2 :3001/oauth2/token con grant_type=client_credentials.
  2. 2
    Llamada a la API Cada servicio Angular llama /api/gw/<servicio>/v1/api/v1/... con Authorization: Bearer. El BFF reenvía al gateway WSO2 :3000.
  3. 3
    Enrutamiento WSO2 enruta al microservicio dentro de Kubernetes (namespace voltera-app). El front nunca habla directo con los pods.

Patrón de URL (ver core/gateway.ts): gw('{{ svc.tarifas }}', 'api/v1/tarifas') → /api/gw/{{ svc.tarifas }}/v1/api/v1/tarifas.
